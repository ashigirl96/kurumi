# Agent SDK はホストで、Claude Code CLI はターンごとのコンテナで動かす

Claude Agent SDK はホストのプロセスで動かし、Claude Code CLI だけを SDK の `spawnClaudeCodeProcess` から `docker run -i --rm` で起動する。ホストとコンテナの通り道は標準入出力だけにし、Turn（ターン）ごとにコンテナを作り直して、会話はセッションごとの `CLAUDE_CONFIG_DIR` から `resume` で続ける。こうすると、ツールの許可判定、ホスト側のツール、ターン途中の割り込みと中断を、独自の通信手順なしで SDK のまま使え、ターンの終わりにコンテナごと消せば孤児になったプロセスも残らない。

確認の範囲: Docker Desktop for Mac で実測した。起動から初期化まで約 0.5 秒、`resume` による上乗せはなかった。Linux では未確認。

## Considered Options

- SDK をコンテナの中で動かし、ホストと独自の JSON 行で話す。割り込み、中断、許可判定の転送を、すべて自前の通信手順で作り直すことになる。
- ループをホストに置き、コンテナはツールを実行するだけにする。Claude Code の組み込みのツールを作り直すことになる。トークンの差し替えはどのみち要る外向き通信の中継に含まれるので、得るものが小さい。
- セッションごとにコンテナを残し、空いたら止める。終わり方が増えるうえ、ターン途中の割り込みで残ったプロセスを抱え続ける。
