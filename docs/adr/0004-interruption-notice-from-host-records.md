# 中断の知らせはホストの記録から作り、会話記録は安全の判断に使わない

Interrupted Turn（中断されたターン）の次のターンでは、ホストが持つ 2 つの記録から中断の知らせを作り、利用者のメッセージの前に置く。1 つは、始まったが結果の分からないツール呼び出しで、ホストの `PreToolUse` フックが許可を返す前に `onFailure: 'block'` で書く。もう 1 つは、配信済みの送信である。会話記録はコンテナの中でエージェントと同じ利用者が書くので、エージェントが書き換えられるうえ、ツールが動き出した直後に中断すると呼び出しが記録に残らない（21 回中 21 回、実測）。そのため、ホストは会話記録を安全に関わる判断に使わない。

確認の範囲: CLI は `PreToolUse` フックの返事を待ってからツールを始め、フックの中でホストを強制終了するとツールは動かなかった（3 回中 3 回、実測）。配信済みの送信を知らせると、中断後の送り直しは 16 回中 15 回から 20 回中 0 回に減った（実測）。ツール呼び出しの知らせの効き目は未確認。

## Consequences

- 会話記録の改ざんは、現時点では許容する。エージェントが自分の会話記録を書き換えることは防がず、影響はそのセッションでエージェントが持つ文脈に限られる。
- 中断の知らせは、重複実行を抑えるものであり、完全には防がない。知らせを受けたエージェントが、それでも同じ操作をやり直すことはありうる。
- 根本的な対策は、Durable Execution とセッション管理を設計するときに改めて検討する。
- フックの記録の書き込みに失敗したら、ツールを止める。既定の `onFailure` のままでは、記録がないままツールが動く。
